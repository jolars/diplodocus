# Julia API extraction

Julia extraction reads `Project.toml`, an explicit `.jl` entry file, and its
unconditional literal includes. Declare `ecosystem: "julia"`,
`metadata-path: "Project.toml"`, and a target with `extractor: "julia"` and
`path: "src/MyPackage.jl"`. Source directories are not valid Julia targets.

To document optional extension implementations, add `julia.extensions` to that
target with package-relative entry files, such as `[ext/MyPackageMakieExt.jl]`.
Their static methods join the existing generics, preserving generic prose and
fallback methods. Selection does not load weak dependencies or infer their
methods. See [explicit extension
sources](https://github.com/jolars/diplodocus/blob/main/docs/ir/julia-extraction.md#explicit-extension-sources) for the
configuration and supported subset.

Exported, `public`, and documented declarations form the maintained surface.
Automatic API navigation, search, and indexes include exported and `public`
bindings, their methods and explicit constructors, and required module
containers. A public alias exposes its canonical item. Documentation alone does
not advertise private helpers, and fields are excluded from automatic indexes.
Retained private items and fields remain available through direct references.
Functions group supplied methods and their prose on the family page with stable
method anchors. Types retain fields and explicit constructors. Static imports
and aliases resolve to maintained declarations. Julia Markdown docstrings supply
prose, lists, tables, admonitions, and inert code examples. API `@ref` links can
name a family or select a method, and they preserve their labels.

During extraction, Julia loads every checkout in the configured package project
and verifies its name, UUID, version, and entry file, even without doctests.
Unresolved public bindings additionally trigger type reflection. Prepare Julia
and the package dependencies before building. The helper verifies the supplied
checkout and completes exported types generated by macros, retaining runtime
provenance separately from source facts. `check` stays static and reports
unresolved generated declarations.

Computed includes, conditional declarations, unsupported macros, unresolved
functions, and unavailable reexports still produce diagnostics. Extraction does
not infer runtime methods. Unsupported documentation syntax
remains visible with warnings. The
[Julia extraction
contract](https://github.com/jolars/diplodocus/blob/main/docs/ir/julia-extraction.md)
defines the supported subset and method identity rules.

Julia `jldoctest` fences execute during extraction in the prepared package project.
The native adapter supports REPL transcripts, script examples with `# output`,
expected errors, named blocks that share state within one API document, and
block-level `setup`, `teardown`, and `output` options. Anonymous blocks get fresh
modules; separate API documents use fresh processes. REPL semicolons suppress
display, and multiline input uses seven spaces for continuation lines. Hidden
output still participates in comparison. Unsupported options, including filters
and `@meta` setup, fail extraction. Ordinary Julia fences remain illustrative.

The adapter retains literal outputs, outcomes, source fingerprints, and runtime
and dependency observations in snapshots. It does not install dependencies or
cache API execution. `check` does not load packages or execute doctests;
`generate` needs no interpreter or source checkout.
